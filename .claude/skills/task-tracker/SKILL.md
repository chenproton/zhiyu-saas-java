# 任务跟踪技能

## 何时使用

✅ 用户明确要求跟踪任务（"创建任务跟踪"、"记录进度"、"跟踪这个任务"）
✅ 复杂的多步骤开发任务
✅ 需要跨会话恢复的工作

❌ 简单的单步操作
❌ 纯咨询性对话

## 核心操作

### 1. 创建任务

**触发**：用户说"创建任务跟踪"、"记录这个任务"

**步骤**：
```bash
# 1. 确保目录存在
mkdir -p docs/tasks/active docs/tasks/archive

# 2. 生成文件名
# 格式: task-{YYYYMMdd-HHMMSS}-{任务简称}.md
TIMESTAMP=$(TZ=Asia/Shanghai date +%Y%m%d-%H%M%S)
SLUG="{任务标题简化版，截断30字符}"
FILENAME="task-${TIMESTAMP}-${SLUG}.md"

# 3. 创建文档
# 填充上述模板内容到 docs/tasks/active/$FILENAME

# 4. 首次使用时创建 README.md（如不存在）
```

**README.md 内容**：
```markdown
# 任务跟踪中心

## 目录说明
- `active/` - 进行中的任务
- `archive/` - 已完成的任务（按月归档）

## 使用方法
1. Claude 自动创建任务跟踪文档
2. 手动编辑文档更新进度（修改复选框）
3. 任务完成后移动到 archive/{年-月}/

## 快速恢复
```bash
# 查看活跃任务
ls -1 active/

# 恢复任务
cat active/task-20260121-*.md
```

### 2. 更新进度

**触发**：用户说"更新进度"、"标记步骤X完成"

**步骤**：
```bash
# 1. 找到当前任务文档（最新的那个）
TASK_FILE=$(ls -t docs/tasks/active/*.md | head -1)

# 2. 更新复选框: - [ ] → - [x]
sed -i "s/^- \[ \] ${STEP_NUMBER}\./- [x] ${STEP_NUMBER}./" "$TASK_FILE"

# 3. 更新时间戳
CURRENT_TIME=$(TZ=Asia/Shanghai date '+%Y-%m-%d %H:%M:%S')
sed -i "s/^\*\*更新时间\*\*:.*/\*\*更新时间\*\*: $CURRENT_TIME/" "$TASK_FILE"

# 4. 添加变更记录
echo -e "### $CURRENT_TIME\n- 完成步骤 $STEP_NUMBER: $DESCRIPTION" >> "$TASK_FILE"

# 5. 重新计算进度百分比
TOTAL=$(grep -c "^- \[.\]" "$TASK_FILE")
DONE=$(grep -c "^- \[x\]" "$TASK_FILE")
PERCENT=$((DONE * 100 / TOTAL))
```

### 3. 列出活跃任务

**触发**：用户说"有哪些任务"、"列出任务"

**步骤**：
```bash
for file in docs/tasks/active/*.md; do
  TITLE=$(grep "^# 任务：" "$file" | sed 's/^# 任务：//')
  STATUS=$(grep "^\*\*状态\*\*:" "$file" | sed 's/.*: //')
  PROGRESS=$(grep "^\*\*已完成\*\*:" "$file" | sed 's/.*: //')
  
  echo "📄 $TITLE"
  echo "   状态: $STATUS | 进度: $PROGRESS"
  echo "   文件: $file"
  echo ""
done
```

### 4. 恢复任务

**触发**：用户说"继续上次的任务"、"恢复任务"

**步骤**：
```bash
# 1. 确定要恢复的任务
if [ 用户指定了任务名 ]; then
  TASK_FILE=$(find docs/tasks/active -name "*{用户指定的关键词}*.md" | head -1)
else
  TASK_FILE=$(ls -t docs/tasks/active/*.md | head -1)  # 最新的
fi

# 2. 读取文档内容
cat "$TASK_FILE"

# 3. 提取关键信息并向用户确认
TITLE=$(grep "^# 任务：" "$TASK_FILE" | sed 's/^# 任务：//')
NEXT_STEPS=$(提取 "下一步操作" 部分)

# 4. 输出恢复信息
echo "正在恢复任务：$TITLE"
echo "下一步操作："
echo "$NEXT_STEPS"
```

### 5. 记录方案讨论

**触发**：用户说"记录方案讨论"、"添加方案"、"方案对比"、"这个方案"

**步骤**：
```bash
# 1. 找到当前任务文档
TASK_FILE=$(ls -t docs/tasks/active/*.md | head -1)

# 2. 在"方案设计"部分添加新方案
# 如果是添加新方案，在"方案讨论"下增加方案 C、D 等
# 如果是记录选择理由，更新"最终选择"部分

# 3. 更新变更记录
CURRENT_TIME=$(TZ=Asia/Shanghai date '+%Y-%m-%d %H:%M')
echo -e "### $CURRENT_TIME\n**变更类型**: 方案讨论\n\n**变更内容**:\n- 添加方案讨论: $DESCRIPTION" >> "$TASK_FILE"
```

**操作指南**：
1. 如果有多个方案，逐个记录每个方案的优缺点
2. 记录方案对比的维度（性能、成本、复杂度等）
3. 明确记录选择理由和权衡考量
4. 保留备选方案，方便后续调整

### 6. 记录技术调研

**触发**：用户说"记录技术调研"、"添加技术选型"、"技术对比"

**步骤**：
```bash
# 1. 找到当前任务文档
TASK_FILE=$(ls -t docs/tasks/active/*.md | head -1)

# 2. 在"技术调研"部分更新技术选型表格
# 添加新的技术对比行

# 3. 更新调研结论

# 4. 添加参考资料链接

# 5. 更新变更记录
CURRENT_TIME=$(TZ=Asia/Shanghai date '+%Y-%m-%d %H:%M')
echo -e "### $CURRENT_TIME\n**变更类型**: 技术调研\n\n**变更内容**:\n- 完成技术调研: $DESCRIPTION" >> "$TASK_FILE"
```

**操作指南**：
1. 对比至少 2-3 个技术方案
2. 记录版本号（避免未来升级时的兼容性问题）
3. 评估学习成本和风险
4. 保存参考资料链接，方便后续查阅

### 7. 记录问题

**触发**：用户说"记录问题"、"遇到问题"、"添加问题"

**步骤**：
```bash
# 1. 找到当前任务文档
TASK_FILE=$(ls -t docs/tasks/active/*.md | head -1)

# 2. 在"问题记录"部分添加新问题
CURRENT_TIME=$(TZ=Asia/Shanghai date '+%Y-%m-%d %H:%M')

# 3. 记录问题的完整信息：
#    - 问题描述
#    - 根本原因
#    - 解决方案
#    - 当前状态

# 4. 如果问题已解决，标记解决时间

# 5. 更新变更记录
echo -e "### $CURRENT_TIME\n**变更类型**: 问题记录\n\n**变更内容**:\n- 记录问题: $PROBLEM_TITLE\n- 状态: $STATUS" >> "$TASK_FILE"
```

**操作指南**：
1. 及时记录问题，避免遗忘细节
2. 详细描述问题现象和影响范围
3. 分析根本原因，不只是表面现象
4. 记录解决方案的详细步骤
5. 问题解决后及时更新状态

### 8. 归档任务

**触发**：用户说"任务完成"、"归档任务"

**步骤**：
```bash
# 1. 更新状态
sed -i "s/^\*\*状态\*\*:.*/\*\*状态\*\*: 🔵 已完成/" "$TASK_FILE"

# 2. 移动到归档目录
YEAR_MONTH=$(TZ=Asia/Shanghai date +%Y-%m)
mkdir -p "docs/tasks/archive/$YEAR_MONTH"
mv "$TASK_FILE" "docs/tasks/archive/$YEAR_MONTH/"

echo "✅ 已归档到: docs/tasks/archive/$YEAR_MONTH/"
```

## 最佳实践

**应该做**：
- ✅ 一个任务 = 一个完整功能开发
- ✅ 及时更新进度（完成一步更新一次）
- ✅ 详细记录关键决策和选择理由
- ✅ 保留原始需求描述
- ✅ **记录方案讨论过程**（多个方案、对比、选择理由）
- ✅ **记录技术调研结果**（技术选型、对比、结论）
- ✅ **及时记录遇到的问题**（问题、原因、解决方案）
- ✅ **下一步操作要有上下文**（依赖、预期结果、为什么这样做）
- ✅ **变更记录要详细**（记录方案调整、决策变更的理由）

**不应该做**：
- ❌ 为每个小改动创建任务
- ❌ 删除旧任务（归档即可）
- ❌ 自动归档（由用户决定）
- ❌ **只记录最终方案，不记录讨论过程**
- ❌ **只记录步骤，不记录为什么这样做**
- ❌ **问题解决了就不记录**（应该记录问题和解决过程）

## 错误处理

**目录不存在** → 自动创建 `docs/tasks/active` 和 `archive`

**没有活跃任务** → 提示用户：创建新任务 | 恢复归档任务 | 查看历史

**文档格式错误** → 尽量解析，提示用户保持格式：
- 保持 `##` 标题层级
- 复选框格式：`- [ ]` 或 `- [x]`
- 不删除 `**字段**` 标记

## 功能边界

**适用于**：单人开发、本地存储、快速恢复上下文

**不适用于**：多人协作、实时同步、复杂依赖管理（请使用专业项目管理工具）
