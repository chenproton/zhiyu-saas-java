# 双栈功能对齐迁移计划（Java 对齐 Go）

> 目标：使 **Java 复制版**（`backend/java/ruoyi-modules/ruoyi-zhiyu` + `frontend/portal-vue`）与 **Go 原始版**（`backend/go` + `frontend/edu`）的前后端功能对齐一致。Go 为功能基准（Source of Truth），Java 为对齐目标。
> 本文件为活文档；分模块差距明细见同目录 6 份 `gap-*.md`。

## 0. 结论摘要

- Java 后端是 Go 的**高保真移植**：接口面（HTTP 端点）、实体/mapper 覆盖、字段覆盖几乎 1:1；Vue 门户同样是 React SPA 的高保真移植。
- **不存在"整模块缺失"**。差距集中在「接口存在但**空实现/静默丢数据**」与「实现深度不足」两类，以及前端个别功能/契约缺口。
- 迁移方向：**补齐 Java 侧的空实现与缺失功能**，使行为与 Go 一致；前端补齐 Vue 缺失页面/API 函数与契约。
