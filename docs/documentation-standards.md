# 文档分层规范（教程 vs 参考 · 放置决策 · 砍废话）

> 借鉴 DeepSeek Harness 的文档纪律（dsh-doc-standards），落地为本仓库的文档组织规范。核心目标：**每个事实只在一个地方「权威地」说清楚，其余地方用链接引用**，砍掉重复、流水账与「文档废话」。
>
> 关联：文字品控见 [`prose-standards.md`](prose-standards.md)；spec 文档见 [`spec-standards.md`](spec-standards.md)；决策记录见 [`decisions/`](decisions/README.md)。

## 一、文档分两类：教程 vs 参考

任何 `docs/` 下的文档，都要能明确归入下面两类之一（从「读者如何使用它」判断，不是从文件名判断）：

| 类型 | 特征 | 读者如何使用 | 本仓库的例子 |
|---|---|---|---|
| **教程（tutorial）** | 引导读者「按顺序做完一件事」，有可观察的结果 | 从第一步读到最后，动手操作 | （暂缺，见「三、当前缺口」） |
| **参考（reference）** | 支持「在明确范围内查找」，无所谓顺序 | 用时翻查，跳着读 | `components.md`（组件速查）、`refactor-layering.md`（红线清单）、`spec/*`（规格） |

**判断口诀**：如果文档要求读者「从头读才能懂」，它是教程；如果读者「哪里不懂查哪里」，它是参考。

## 二、放置决策（一个事实一个家）

写/移动文档前，先回答四个问题：

1. **这个事实属于哪个主题？** 放到它「最权威的拥有者」那里。
2. **是教程还是参考？** 混合体要拆分：主体用一种形式，少量另一种形式放进明确标注的小节。
3. **会被谁读？** 给 AI 协作者的契约（红线、分层、复用优先）放 `AGENTS.md` 或 `docs/`，别埋进注释；给最终用户的文案放 spec/PRD。
4. **会不会频繁改动？** 频繁变的内容优先放「无配对成本」的位置（本仓库暂无双语配对机制，故无此约束，但原则保留：易变的放单一来源）。

**分层原则**：一个主题的「完整细节」只在其直接归属的文档里展开；上级文档只概括目的、职责、高层行为，深度细节用链接下放到下级文档。

现有文档的权威归属（勿重复、勿另起炉灶）：

| 主题 | 权威文档 |
|---|---|
| 后端分层红线（handler/store/service 职责） | `refactor-layering.md` |
| 前端组件复用速查 | `components.md` |
| 表单/表格架构盘点 | `forms-tables.md` |
| AI 功能统一底座 | `ai-development.md` |
| 快照版本机制 | `resource-snapshot-versioning.md` |
| 全平台能力规格 | `spec/01~05` |

## 三、当前缺口（写作方向）

本仓库 `docs/` 目前**几乎全是参考型**，缺教程型。以下内容若能落地为「教程」，价值最高：

- 新租户开通到第一门课的完整操作路径（面向运营/管理员）。
- 「新增一个后端模块」或「新增一个前端页面」的 step-by-step 开发教程（面向 AI 协作者）。

> 这些课程序章先用「读者是谁、做完能做什么」一句话立项，不必现在写全。

## 四、砍「文档废话」（slop checklist）

写/审文档时，按此清单删除多余内容（详细判据见 `prose-standards.md`「文字品控」）：

1. **推理过程泄漏**：`先 A 后 B 再 C` 的流水账、`尝试了 X 失败改 Y` 的过程描述、`TODO: 待确认` 的残留、设计会议的纪要式引用。
2. **重复说明**：同一契约在多个文件重复，保留一个权威处，其余用链接。
3. **代码复述**：注释/文档只是把代码逐行翻译成中文，没有补充「为什么」。
4. **状态噪音**：`已实现`、`待办`、`建议`、版本历史流水，除非是决策记录（ADRs）或变更日志的职责。
5. **装饰性措辞**：`很明显`、`值得注意的是`、`如上所述`、空洞的客套。
6. **手工维护的目录/清单**：能用脚本/生成器产出的（如接口清单、测试清单），不要手写维护，写生成器或链接。

**保留原则**：砍掉的是「叙事、重复、装饰」，**不是「契约、边界、为什么」**。任何「删了会导致读者误解或误改代码」的内容都必须留下。

## 五、移动/删除/改名文档时的原子性

- 移动文档 = 从旧位置删除 + 加入新位置 + 修复所有指向它的链接（Markdown 链接、代码注释里的 `docs/*.md` 引用、`AGENTS.md` 的引用），**在同一 commit 内完成**。
- 删除文档前，先 `grep -rn` 搜索所有引用，确认无悬空链接。
- 改名（尤其编号文档如 `01-prd.md`）要同步改所有引用。

## 六、验证清单（写/审文档后自检）

- [ ] 能明确说出这份文档是「教程」还是「参考」。
- [ ] 每个事实只有一个「权威家」，其余是链接。
- [ ] 没有推理过程泄漏、代码复述、状态噪音。
- [ ] 移动/改名时，所有 inbound 链接已同步修复。
- [ ] 纯文案改动未改变任何「承诺的行为」（若改了行为而非解释，走 ADR 或 spec 更新）。
