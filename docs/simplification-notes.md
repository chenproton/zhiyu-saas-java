# 简化审计与 Agent Note（找可以简化的地方）

> 借鉴 DeepSeek Harness 的 simplification 纪律（dsh-find-simplifications），落地为本仓库的「找简化点」流程。目标：把「找可简化之处」从零散直觉，变成**有证据、可记录、可追溯**的 Agent Note，避免误删「有意为之」的设计。
>
> 关联：决策记录见 [`decisions/README.md`](decisions/README.md)；拆分「简化」与「改行为」的边界，见下文「五、安全边界」。

## 一、先读「为什么」再找「该删什么」

动手前必读，避免把「有意为之」当冗余删掉：

1. `AGENTS.md` 三「开发原则」（简单优先、核心加锁、复用优先）。
2. `docs/decisions/` 相关 ADR——尤其 `0003`（租户隔离「SQL 层可选限定」是刻意的，不是漏写）、`0001`（分层红线）。
3. `docs/refactor-layering.md`、`docs/components.md`（已有的复用/收敛约定）。

**默认「有意为之」的东西，不要当「低费力可删」处理**（除非用户明确要求）：AGENTS.md 里明示的防御分支、刻意的双实现、`0003` 里「handler 校验为主」的租户策略等。

## 二、什么算「强简化候选」（有证据，不是猜）

一个候选要「移除/折叠了真实的东西」且「能证明当前设计成本 > 收益」：

- 公开方法/字段/配置项/事件/helper **没有生产消费者**（测试或文档是唯一消费者，且不承重）。
- 两份表示镜像同一事实（尤其跨多个事件/状态/缓存）。
- 一个 seam 的方法每个实现都必须支持，但没有任何消费者用。
- 一个独立包只为了 test/demo/support 存在，徒增维护成本。
- 实现了**speculative 的通用性**：多会话、后台任务、实时失效、无人需求的产品功能（对照 `spec-standards.md`「扩展性预留」是否已声明「不做」）。
- 手工代码重写了「现成依赖/内建」已提供的能力（且替换能删实现+专属测试）。

**弱候选不够格记 Note**：删一个 typo、跑一次 linter、删掉有文档说明的「有意为之」、泛泛说「看起来复杂」而没有调用点证据。

## 三、审计方法

1. **先给范围**：明确审哪个目录/哪类代码（后端 store / 前端组件 / packages），不默认全仓。
2. **广撒网**：用并行子代理，每个代理一个领域（如「后端 store」「前端组件」「packages」），要求**给证据（调用点、consumer）而非猜测**。
3. **从最大的生产代码增量开始**：只扫「明显未用符号」会漏掉「重复的生命周期/防御机制」这些真正的大成本。
4. **画所有权图**：对复杂异步代码，把每个哨兵/准备 Promise/取消路径/disposer/状态标记映射到唯一 owner；多个机制镜像同一「存活/结算」事实 → 提议合并成一个。
5. **每个候选给出证据**：`grep -rn` 调用点数量、consumer 是谁、vs ADR/spec 的冲突点。

## 四、简化想法写进 Agent Note（记录格式）

凡是有价值的简化想法，写成一条 **Agent Note**，放在 `docs/decisions/` 下（与 ADR 同目录，但用「提议」状态，区别于「已接受决策」）：

```
# 简化候选：<一句话>

- 状态：提议（未实施）
- 涉及：<文件/符号>
- 证据：<调用点数量、consumer、为何当前成本 > 收益>
- 建议动作：<删除 / 折叠 / 降级，具体到符号>
```

**未实施前不要动代码**；由用户确认后，再落地实施（并更新状态为「已接受」，或改记一条 ADR）。

## 五、安全边界（什么时候是「简化」，什么时候是「改行为」）

- **简化**：行为不变或仅极轻微变化且更容易解释，只删实现/样板/重复。
- **改行为**：删掉后「承诺的行为」变了——不能当简化随手做，要先走 `spec-standards.md` 的 spec 一致性或 ADR。

**一句话判定**：如果我删了这个东西，**未来会有用户/协作者发现「某个能力没了」吗？** 会 → 这是改行为，走 spec/ADR；不会 → 这是简化，可记 Note。

## 六、自检

- [ ] 已读「为什么」（AGENTS.md + ADRs），确认候选不是有意为之。
- [ ] 每个候选都有调用点/consumer 证据，不是「看起来复杂」。
- [ ] 区分了「简化」与「改行为」，后者走 spec/ADR。
- [ ] 想法记成了 Agent Note（提议态），未擅自改代码。
