# 前端功能对齐差异表（React `frontend/edu` ↔ Vue `frontend/portal-vue`）

> 日期：2026-08-19 · 基准：React SPA 路由表（`frontend/edu/src/routes.tsx`，174 条解析路由 ≈ 139 个页面路由）vs Vue 业务门户（`frontend/portal-vue/src/router/index.ts`，89 条路由）。
> 方法：脚本解析两端路由表，路径归一化（去 `/edit`、`/new`、`/add` 后缀，`:resultId`→`:id`）后逐条对比；`<Navigate>`/`index` 跳转路由不计入页面。
> 结论：**无法平滑复制**（框架 React 19 vs Vue 3.5、UI Tailwind+自研 vs Element Plus、数据层 @zhiyu/api-client vs 手写 @/api 均不互通），以 React 为唯一基准逐页重写 Vue。范围仅 portal-vue 业务门户（用户决策：不含 superadmin/changelog/plus-ui；视觉沿用 Element Plus；按 React 路由顺序推进）。

### 2.1 重要发现：三类「缺失」实际非独立工作量

逐页核对 React 源码后发现，缺失清单中相当一部分**不需要从零翻译**：

| 类别 | 页面 | 说明 |
|---|---|---|
| **别名转发页（6 条）** | affairs 的 `majors`、`org-structure`、`positions`、`relations`、`students`、`teachers` | React 页面仅为 `export { default } from '@/app/portal/apps/system/.../page'`，与 `portal/apps/system` 共享同一组件。**Vue 侧在 M7 实现 system 组件后，affairs 路由复用同一组件即可，不重复翻译** |
| **共享组件页（2 条）** | 各域 `workflows`、`batches` | React 用共享 `WorkflowConfigPage` / `BatchGroupPage`；Vue 已有统一 `workflows/index.vue`（流程配置）与各域 batches 页，以核对覆盖度为主 |
| **聚合页覆盖（3 条）** | 各域 `approvals`、affairs `config`、affairs `archive` | React 按域拆分（`affairs/approvals` 238 行）；Vue 为统一「审批中心」（按 targetType 筛选）与「场地节次配置」（scheduling-config.vue 294 行），功能等价则以核对修正为主，不新写 |

**修正后估算**：真正需要从零新写的核心页面集中在 portal 域（apps/alliance 28 + apps/system 17 + apps/ai 15 + alliance 前台 15）与各域详情/编辑/学习页（teaching-plans/:id 492 行、landing/:id/learn 等），实际独立工作量显著小于 128 页。

## 四、每页对齐核对标准（六项，逐页对照 React 验收）

1. **路由**：路径与 React 一致（含动态段），嵌套 layout 等价；
2. **字段**：表单字段、列表列、筛选条件与 React 完全一致（字段名/标签/顺序）；
3. **校验**：必填、格式、长度、唯一性校验规则一致；
4. **分页**：`limit/offset` 参数、`{items,total}` 返回、空态/加载态一致；
5. **错误分支**：失败提示、401 跳转、403 权限提示与 React 一致；
6. **权限点**：按钮级显隐权限字符串与 React（`RequireMenu`/菜单权限）一致。

> 视觉不逐像素对齐：Element Plus 原生风格；交互细节（弹窗确认文案、操作顺序、禁用态）与 React 一致。
