# 全仓库文字品控规范（Prose Standard）

> 借鉴 DeepSeek Harness 的 prose 纪律（dsh-prose-standard），落地为本仓库的文字品控标准。覆盖 **Markdown、JSDoc、代码注释、测试注释、提示词、CLI/UI 文案** 六大类文字的「该不该写、怎么写」。
>
> 关联：文档分层见 [`documentation-standards.md`](documentation-standards.md)；spec 文档见 [`spec-standards.md`](spec-standards.md)。

## 一、总原则

**写够「保住契约」的文字，删掉「推理过程、重复、装饰」。**

「契约」= 调用方/实现方/生产者/消费者所依赖的**义务、不变量、前置条件、后置条件、兼容性承诺**。

判断某段文字该不该留，自问：**删掉它，会不会导致有人误改代码、误解接口、或重新踩一个已经踩过的坑？** 会 → 留；不会 → 删。

**注释描述「代码无法表达的、非显然的契约或理由」，不复述代码已经显式表达的东西。**

## 二、六大类的「保什么、砍什么」

### 1. Markdown（docs/ 与 spec/）

- **保**：契约型事实（红线、边界、状态机、错误码语义）、非显然的架构理由、扩展性预留（「明确不做」）。
- **砍**：流水账、过程逆推、`待确认` 残留、跨文件重复（保留一个权威处 + 链接）。

### 2. JSDoc（TS 公共 API 注释）

- **保（公共 JSDoc 必写）**：调用方可观察的返回区分、抛错/拒绝、副作用、所有权（谁负责释放）、时序、取消、持久化。
- **砍**：参数名逐字复述、`// set x` 式实现复述、实现细节。

### 3. 代码注释（Go/TS 内部注释）

- **保**：非局部的结构（跨文件约定）、明显复杂的局部结构（不变量、竞态顺序、所有权、安全边界、令人意外的失败行为）。
- **砍**：控制流叙事（`// 先查再插` 复述 if）、代码复述、冗余的 `why`（能一眼看懂的）。

### 4. 测试注释

- **保**：非显然的测试设计——为什么用这个 fixture、为什么绕道断言、为什么需要真实入口、为什么间接观测。
- **砍**：测试步骤逐行走读、断言清单复述。

### 5. 提示词（AI 功能里的 system/user prompt）

- **保**：稳定对外可见的提示文本改动要当作**行为变更**对待，需回归校验。
- **砍**：模型收到的无关概念、内部执行叙事。

### 6. CLI / UI 文案（含错误信息、toast、placeholder、按钮）

- **保**：错误信息必须**点名失败主体/路径 + 违反的规则 + 非显然的纠正方式**（例：「题目导出失败：第 3 行缺少题目标题」优于「导出失败」）。
- **砍**：内部执行叙事（`数据库连接失败` 这种暴露内部实现的，除非对排障必要）、无信息量的 `失败`/`错误` 裸词。
- **UI 文案是行为**：改动用户可见文案要当功能改动对待，不做视觉验证但需人工确认。

## 三、术语纪律

本仓库的领域术语要统一，避免「同一概念多词」：

| 概念 | 规范用词 | 避免 |
|---|---|---|
| 多租户隔离单位 | 租户（tenant） | 校区/客户混用 |
| 岗位能力建模 | 岗位 → 职责 → 能力点 | 能力模型混称 |
| 试卷/测评/考试 | 按上下文区分「试卷」（exam）、「测评」（evaluation）、「考试安排」（exam usage） | 一律叫「考试」 |

> 术语表待建立，当前先以 `docs/spec/` 里的措辞为基准；发现新术语不一致时，在此表补充。

## 四、写/审文字的标准动作

1. **先明确 scope**：审哪些文件、哪种语言（Go/TS/Markdown）、哪些目录。不默认全仓。
2. **排除项**：`backend/vendor/`、`node_modules/`、`.next/`、`dist/`、`*.tsbuildinfo`、`logs/`、`offline/`、`apps/edu/public/image-editor`（符号链接），见 `AGENTS.md` 八.6。generated 产物（生成器产出）不改手，改生成器源 + 重新生成。
3. **每段保留完整命题**：改文字前先识别其「演员、动作、条件、时序、情态（must/may/never）、负向保证、所有权、副作用、失败模式、后果」，删精简时确保每个真实条款都存活。
4. **一个解释一个家**：同一「为什么」只在拥有它的地方写全，别处链接。
5. **review/audit 只报告不 edit**：审文字时输出 findings；只有明确被要求「写/改/砍」时才改。

## 五、自检清单

- [ ] 留的文字都是「契约/边界/为什么」，没有推理过程、重复、装饰。
- [ ] 公共 JSDoc 说清了返回/抛错/副作用/所有权/时序。
- [ ] 错误文案点名了主体+规则+纠正。
- [ ] 术语与 spec/本表一致。
- [ ] 删文字没有改变「承诺的行为」（若改变，走 ADR 或 spec 更新）。
