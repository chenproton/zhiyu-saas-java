# 初始化与部署指南（base-dev-framework6-java）

> 本文档指导从零初始化并部署公司研发基础框架（前后端一体化仓库）。所有路径、端口、账号均与仓库实际配置逐项核对，以本文为准。

## 1. 环境要求

| 依赖 | 版本要求 | 用途 |
|------|---------|------|
| JDK | 21+ | 后端 |
| Maven | 3.9+（或仓库自带 `mvnw` / `mvnw.cmd`） | 后端构建 |
| Node.js | >= 20.19.0 | 前端 |
| pnpm | >= 10.0.0（建议与 `frontend/plus-ui/pnpm-lock.yaml` 一致） | 前端 |
| MySQL | 8.0+ | 主数据库 |
| Redis | 6.0+（必须配置密码） | 缓存 |
| Docker | 可选（推荐部署方式） | 容器编排 |
| Git | 任意 | 拉取代码 |

## 2. 初始化数据库

### 2.1 准备 MySQL

**方式 A：Docker 一键启动**（推荐，随仓库编排）

```bash
docker compose -f backend/java/script/docker/docker-compose.yml up -d mysql
```

- 镜像 `mysql:8.4.9`，端口 3306，root 密码 `root`
- 自动建库 `ry-vue`（utf8mb4 / utf8mb4_general_ci，`lower_case_table_names=1`）
- 数据目录 `/docker/mysql/data`（需预先创建并授权）

**方式 B：本机安装 MySQL 8+**，手工建库：

```sql
CREATE DATABASE IF NOT EXISTS `ry-vue` DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;
```

### 2.2 导入初始化脚本

脚本位于 `backend/java/script/sql/`（根目录为 MySQL 脚本；Oracle / PostgreSQL / SQLServer 使用对应子目录 `oracle/`、`postgres/`、`sqlserver/`）：

| 脚本 | 用途 | 必装 |
|------|------|------|
| `ry_vue.sql` | 主库：用户、角色、菜单、部门、字典、参数、日志、文件等全部基础数据 | ✅ 必装 |
| `ry_workflow.sql` | 工作流（Warm-Flow）相关表 | 按需 |
| `ry_job.sql` | SnailJob 调度中心表（含 `sj_group_config`、`sj_namespace` 接入令牌） | 按需（启用 SnailJob 时） |
| `ry_ai.sql` | SnailAI 相关表 | 按需（启用 SnailAI 时） |

导入示例（MySQL）：

```bash
mysql -h127.0.0.1 -uroot -proot ry-vue < backend/java/script/sql/ry_vue.sql
# 按需继续导入：
# mysql -h127.0.0.1 -uroot -proot ry-vue < backend/java/script/sql/ry_workflow.sql
```

### 2.3 默认账号

| 账号 | 密码 | 说明 |

| `admin` | `admin123`（以 `ry_vue.sql` 初始化数据为准） | 超级管理员，**首次登录后请立即修改** |
| `test` / `test1` | `666666` | 演示账号（本部门及以下 / 仅本人数据权限） |

## 3. 本地开发启动

### 3.1 后端

1. **修改本地配置** `backend/java/ruoyi-admin/src/main/resources/application-dev.yml`：
   - **MySQL**：`spring.datasource.dynamic.datasource.master`，默认 `jdbc:mysql://localhost:3306/ry-vue`，账号 `root` / `root`
   - **Redis**：`spring.data.redis`，默认 `localhost:6379`，密码 `ruoyi123`，db 0（单机 / 集群二选一，另一个注释掉）

2. **启动**（二选一）：
   - IDE：运行 `ruoyi-admin` 下 `org.dromara.DromaraApplication`
   - 命令行：

   ```bash
   ./mvnw spring-boot:run -pl ruoyi-admin
   ```

   默认激活 `dev` 环境，端口 `8080`。

### 3.2 前端

```bash
cd frontend/plus-ui
pnpm install        # 首次安装依赖（建议 pnpm i --frozen-lockfile）
pnpm dev            # 默认 http://localhost:80
```

- 开发代理：`/dev-api` → `http://localhost:8080`（配置于 `frontend/plus-ui/vite.config.ts`，改 `.env.development` 的 `VITE_APP_BASE_API`）
- 接口加密默认开启：前端 `VITE_APP_ENCRYPT=true` 与后端 `api-decrypt` 对应，RSA 密钥更换需前后端同步

### 3.3 访问

| 地址 | 说明 |
|------|------|
| http://localhost:80 | 前端管理端页面 |
| http://localhost:8080 | 后端服务 |
| http://localhost:8080/swagger-ui/index.html | 接口文档（SpringDoc） |

## 4. 生产构建

### 4.1 后端

```bash
mvn clean package -P prod        # 默认跳过测试
```

产物：`backend/java/ruoyi-admin/target/ruoyi-admin.jar`

### 4.2 前端

```bash
cd frontend/plus-ui
pnpm install
pnpm build                      # 产物在 frontend/plus-ui/dist
```

### 4.3 jar 直接部署

```bash
java -jar backend/java/ruoyi-admin/target/ruoyi-admin.jar --spring.profiles.active=prod
# 或设置环境变量 SPRING_PROFILES_ACTIVE=prod
```

- 生产配置在 `backend/java/ruoyi-admin/src/main/resources/application-prod.yml`（数据库、Redis、外置服务开关等）
- 文件上传临时目录 `/basic/server/temp`（prod 已配置 `spring.servlet.multipart.location`），Docker 部署由 compose java-backend tmpfs 挂载保证可写（read_only 容器必需，见 `deploy/docker-compose.yml`）

## 5. Docker 部署（推荐）

编排文件：`backend/java/script/docker/docker-compose.yml`

### 5.1 服务清单

| 服务 | 镜像 | 端口 | 说明 |
|------|------|------|------|
| `mysql` | mysql:8.4.9 | 3306 | 主库（数据 `/docker/mysql/data`） |
| `redis` | redis:8.6.3 | 6379 | 缓存（配置 `/docker/redis/conf/redis.conf`，数据目录需 `chmod 777`） |
| `minio` | pgsty/minio | 9000 / 9001 | 对象存储（控制台账号 `ruoyi` / `ruoyi123`） |
| `nginx-web` | nginx:1.31.1 | 80 / 443 | 前端静态资源 + 反向代理 |
| `ruoyi-server1` | ruoyi/ruoyi-server:6.0.0 | 8080（+28080/38080） | 后端实例 1 |
| `ruoyi-server2` | ruoyi/ruoyi-server:6.0.0 | 8081 | 后端实例 2（可水平扩展） |
| `ruoyi-monitor-admin` | ruoyi/ruoyi-monitor-admin:6.0.0 | 9090 | 监控中心（按需） |
| `ruoyi-snailjob-server` | ruoyi/ruoyi-snailjob-server:6.0.0 | 8800 / 17888 | SnailJob 调度中心（按需） |
| `ruoyi-snailai-server` | ruoyi/ruoyi-snailai-server:6.0.0 | 8900 / 18888 | SnailAI 服务（按需） |

### 5.2 重要说明

- **全部使用 `host` 网络模式**：容器端口直接占用宿主机端口，注意与已有服务冲突
- 数据 / 配置目录（`/docker/mysql`、`/docker/redis`、`/docker/nginx`、`/docker/minio`、`/docker/server1|2` 等）需**预先创建**并授权；Redis 数据目录执行 `chmod 777 /docker/redis/data`（见 `backend/java/script/docker/redis/data/README.md`）
- 应用镜像 `ruoyi/ruoyi-*:6.0.0`：从公司镜像仓库拉取，或按 5.3 本地构建

### 5.3 本地构建应用镜像

先完成 4.1 后端构建，然后：

```bash
docker build -t ruoyi/ruoyi-server:6.0.0 backend/java/ruoyi-admin/
docker build -t ruoyi/ruoyi-monitor-admin:6.0.0 backend/java/ruoyi-extend/ruoyi-monitor-admin/
docker build -t ruoyi/ruoyi-snailjob-server:6.0.0 backend/java/ruoyi-extend/ruoyi-snailjob-server/
docker build -t ruoyi/ruoyi-snailai-server:6.0.0 backend/java/ruoyi-extend/ruoyi-snailai-server/
```

> Dockerfile 说明：`backend/java/ruoyi-admin/Dockerfile` 基于 bellsoft JDK 21，入口 `java -jar app.jar`，支持 `SERVER_PORT` / `SNAIL_JOB_PORT` / `SNAIL_AI_PORT` 环境变量（集群多实例时分别指定）。

### 5.4 启动

```bash
# 只启动基础设施（数据库 / 缓存 / 存储 / Nginx）
docker compose -f backend/java/script/docker/docker-compose.yml up -d mysql redis nginx-web minio

# 全部拉起（含应用与按需外置服务）
docker compose -f backend/java/script/docker/docker-compose.yml up -d

# 查看状态 / 停止
docker compose -f backend/java/script/docker/docker-compose.yml ps
docker compose -f backend/java/script/docker/docker-compose.yml down
```

### 5.5 前端与 Nginx

- 将 `frontend/plus-ui/dist` 内容放入 `/docker/nginx/html`（容器内 `/usr/share/nginx/html`）
- Nginx 配置：`backend/java/script/docker/nginx/conf/nginx.conf`（映射 `/docker/nginx/conf/nginx.conf`）
  - `location /`：前端静态资源
  - `location /prod-api/`：反向代理到 `upstream server`（默认 127.0.0.1:8080 / 8081），前端生产环境 `VITE_APP_BASE_API=/prod-api`
  - `location ~ actuator`：拒绝外网访问（返回 403）
- HTTPS：证书放入 `/docker/nginx/cert`，按 nginx.conf 中注释示例开启 443

### 5.6 仅测试用数据库（可选）

`backend/java/script/docker/database.yml` 提供 Oracle / SQLServer / PostgreSQL 测试镜像（**正式环境请自行安装数据库**），与主库异构切换演示用。

## 6. 外置服务启用（默认关闭）

三个外置服务默认 `enabled: false`，按需启用：

### 6.1 monitor-admin（监控中心）

- 启动 `backend/java/ruoyi-extend/ruoyi-monitor-admin`（端口 9090，默认账号 `ruoyi` / `123456`）
- 后端 `application-prod.yml`：`spring.boot.admin.client.enabled: true`，`url: http://localhost:9090/admin`

### 6.2 SnailJob（分布式任务调度）

- 数据库已导入 `ry_job.sql`
- 启动 `backend/java/ruoyi-extend/ruoyi-snailjob-server`（8800 控制台 / 17888 调度端口）
- 后端 `application-prod.yml`：`snail-job.enabled: true`；`group` / `token` / `namespace` 默认值见配置，与 `ry_job.sql` 中 `sj_group_config`、`sj_namespace` 表数据对应

### 6.3 SnailAI

- 数据库已导入 `ry_ai.sql`
- 启动 `backend/java/ruoyi-extend/ruoyi-snailai-server`（8900 控制台 / 18888 gRPC）
- 后端 `application-prod.yml`：`snail-ai.enabled: true`；`app-id` / `token` 在 Server「应用管理」页面创建后填入
- 依赖 RAG 服务（Docling :5100、PaddleOCR :8866，按需，见 docker-compose 环境变量）

## 7. 多环境与配置要点

- **profile**：`local` / `dev`（默认）/ `prod` 三个环境。`mvn -P <id> package` 构建时通过 `@profiles.active@` 占位符写入 `spring.profiles.active`
- **生产敏感配置**（数据库 / Redis 密码、SnailJob / SnailAI 令牌、接口加密 RSA 密钥）建议通过环境变量或外部配置覆盖，勿直接提交明文到代码仓库
- **接口加密**：前端 `VITE_APP_ENCRYPT` 与后端 `api-decrypt` 开关必须一致；RSA 密钥更换需前后端同步替换
- **文件上传**：生产临时目录 `/basic/server/temp`（已配置，`spring.servlet.multipart.location`）；Docker read_only 容器下该目录由 compose java-backend tmpfs 挂载（`/basic/server/temp:noexec,nosuid,size=100m`）保证可写，缺失会导致 multipart 导入/上传 400 bad multipart

## 8. 常见问题

| 问题 | 处理 |
|------|------|
| 端口被占用（80/8080/8081/9090/17888/18888/8900/8800/9000/9001） | host 网络模式下端口直接占宿主机；停用冲突服务或调整端口 |
| Redis 连接失败 | Redis 必须配置密码（默认 `ruoyi123`）；单机 / 集群配置二选一，另一个注释掉 |
| SQL 导入报错 | 确认库名 `ry-vue`、编码 utf8mb4；Oracle/PostgreSQL/SQLServer 请使用 `backend/java/script/sql` 对应子目录脚本 |
| 接口返回加密解析异常 | 前端 `VITE_APP_ENCRYPT` 与后端 `api-decrypt.enabled` 开关不一致，或 RSA 密钥前后端不匹配 |
| 默认账号登录失败 | 密码以 `ry_vue.sql` 初始化数据为准 |
| 日志出现外置服务连接告警 | 未启用 monitor / snail-job / snail-ai 时属正常，保持对应 `enabled: false` 即可 |
| Docker 数据目录权限 | 先创建 `/docker/*` 目录并授权；Redis 数据目录需 `chmod 777 /docker/redis/data` |
