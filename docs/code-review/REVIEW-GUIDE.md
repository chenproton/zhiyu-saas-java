# 全量代码审查指南（子代理必读）

## 你的任务
逐个文件**完整逐行阅读**（禁止抽样、跳读、只读开头结尾）。每个文件读完后再看下一个。只做审查与报告，**禁止修改任何源代码**。

## 审查优先级（用户明确指示，违反以下原则的问题不要报）
1. 简单优先：不过度防御。小概率异常宁可容忍（用户重启恢复即可）。不要报"缺重试""缺兜底""缺参数校验"这类低价值问题。
2. 安全只排高危：只报①未鉴权接口/越权（能访问他人数据）、②敏感信息泄露（密码/密钥/token 回传前端或写日志）、③SQL 注入、④上传文件任意执行。不做深入渗透、不报 CSRF/频率限制缺失。
3. 性能与稳定性优先：核心业务接口的 N+1 查询、无 LIMIT 的全表扫描、循环内逐条 SQL、goroutine/资源泄漏、明显竞态、无超时的外部调用要报。非核心接口允许慢。
4. 容忍 hacker 行为：恶意参数、重复点击普通业务等，只要正常流程不受影响不报。
5. 锁只给核心业务：核心提交（如考试交卷、报名、订单）缺防重/锁要报；普通业务允许重复插入，不报。

## 后端专项红线（违反必报，规范见 docs/refactor-layering.md）
- handler 层出现 SELECT/INSERT/UPDATE/DELETE 或直接 db.Query/QueryRow/Exec（含 import/export/template）
- service 层拼接 SQL 字符串
- store 层读取 HTTP 请求/Claims
- handler 持有 *pgxpool.Pool 字段
- 新接口无 handler/service/store 任一测试（仅提示，P2）

## 前端专项
- 明显 bug：状态未清空、闭包过期值、异步竞态、key 缺失、条件渲染错误
- 内存泄漏：未清理的定时器/监听器
- API 返回错误未处理导致误导用户（如失败弹"成功"）
- 重复组件/重复函数 ≥3 处 → 记入"复用候选"，描述可抽象方式
- 敏感信息写 console/前端存储

## 严重级别
- P0：安全高危 / 数据损坏 / 核心流程必现错误
- P1：性能热点 / 稳定性隐患 / 非必现但影响核心功能
- P2：维护性 / 一致性 / 可读性 / 复用候选

## 排除项（不要检查）
backend/vendor/、node_modules/、.next/、dist/、*.tsbuildinfo、logs/、offline/、apps/edu/public/image-editor、*.lock、*.map、生成产物

## 报告模板（每个文件一段）
```
## `path/to/file.xx`（N 行）
- 完整逐行检查：完成
- [P0] L行号: 问题描述（最佳实践: 建议）
- [P1] L行号: ...
- [P2] L行号: ...
- 复用候选: 与哪些文件重复了什么（若无则省略）
```
无问题的文件也要有段落，写明"未发现问题"。
行号必须真实准确（用 read 工具核对）。
报告写入指定输出文件。返回给主代理的信息只要：每文件 问题数(P0/P1/P2)，以及复用候选总数。
