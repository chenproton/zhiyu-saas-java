# 安全非功能规范（密码 / 会话 / 备份 / 密钥 / 限流 / 上传）

> 本文档定义多租户 SaaS 的**安全非功能需求**，作为 AGENTS.md「三、硬性架构约束 3.3 安全红线」的细则补充。
> 每条注明「现状」与「要求」，并标记 `[已实施]` / `[待实施]`。`[待实施]` 项是**明确的规范承诺**，落地前 spec 与代码允许存在已知差距，但不得声称已实施；落地须走「新功能七节点闭环」并更新状态。

## 1. 密码策略

| 项 | 要求 | 状态 |
|----|------|------|
| 存储 | bcrypt（cost ≥ 10）哈希，禁用明文/可逆加密 | `[已实施]`（`users.password_hash`） |
| 最小强度 | 长度 ≥ 8；至少含字母与数字（大小写/特殊字符不强求，避免过度防御） | `[待实施]`：新增/改密/重置入口统一校验 |
| 历史/轮换 | 不强制定期改密（对 C 端与教师群体是负担）；仅「泄露/可疑活动」时强制重置 | `[已实施]`（按需重置） |
| 重置密码回显 | 明文密码**仅在重置响应中一次性返回**（预览/复制）；服务端不存明文、不打日志、不支持事后再次查询；优先「随机密码仅返回一次」模式 | `[已实施]`（现状即一次性预览） |
| 登录防爆破 | 限流（见 §5）+ 验证码（见 §5），连续失败不返回「用户名 vs 密码」区分 | `[已实施]`（限流）/ `[待实施]`（失败提示统一化） |

## 2. 会话与 JWT 生命周期

- **签名**：HS256，密钥 `JWT_SECRET`（≥ 32 字节随机串，禁止提交仓库）。
- **有效期**：7 天（现状）。要求向「短期 access（≤ 30 分钟）+ 刷新 token（7 天，可撤销）」演进，降低泄露窗口。
- **平台隔离**：portal / saas / partner 三端 token 不可互用（Claims 携带 platform，中间件校验）。
- **吊销语义**：
  - 停用用户 / 停用租户 / 删除用户：存量 token 必须在**下一次请求**失效（`[已实施]`：auth 中间件逐请求校验 user/tenant status）。
  - 修改密码后：旧 token 应失效（`[待实施]`：token_version 列或 issued_at 校验，避免改密后旧会话仍可用）。
  - 主动登出：当前为前端清 localStorage（无服务端吊销）；`[待实施]` 刷新 token 体系中登出应吊销刷新 token。
- **Claims 最小化**：只放 userId/tenantId/roleCodes/permissions/platform，不放密钥、密码哈希等敏感信息。

## 3. 数据备份与灾难恢复

| 项 | 要求 | 状态 |
|----|------|------|
| 数据库 | 每日全量备份 + 持续 WAL 归档（PITR 点时间恢复），保留 ≥ 30 天 | `[待实施]`（运维项，需部署环境） |
| 上传文件 | 与 DB 备份同频异地备份（`data/uploads/` 独立于镜像生命周期） | `[待实施]` |
| 恢复演练 | 每季度一次恢复演练，验证备份可还原 | `[待实施]` |
| 回滚 | 应用回滚走 `git checkout <tag>` + `./deploy.sh`（禁手动登服务器改代码）；DB 回滚走 migration `.down.sql`（不可逆项见 spec-check 提示） | `[已实施]` |

## 4. 密钥管理

| 密钥 | 用途 | 要求 | 状态 |
|------|------|------|------|
| `JWT_SECRET` | 签发 JWT | ≥ 32 字节随机；每 90 天轮换（支持新旧双密钥并存、旧验签新签发）；禁止提交仓库（`.env`） | `[已实施]`（禁提交）/ `[待实施]`（轮换） |
| `AI_CONFIG_SECRET` | 加密租户 AI api_key | **独立密钥，禁止回落 `JWT_SECRET`**；每 90 天轮换（旧密文可解密、新写入用新钥） | `[待实施]`：现状缺省回落 JWT_SECRET，需改造为独立必填 |
| 租户 AI api_key | 调用第三方 LLM | 入库加密（AES），永不回传前端、禁止打日志；只展示脱敏尾号 | `[已实施]` |

## 5. 限流与防爆破

- **现状**：登录 6 接口（`/auth/login`、`/auth/saas/login`、`/auth/portal/login`、`/auth/partner/login`、`/auth/partner/register`、`/auth/select-tenant`）+ `/auth/captcha` + `/files/upload` + 导入导出已挂限流器（Redis 计数，未配置 Redis 自动降级为内存限流）。
- **验证码**：字符验证码，连续输错 3 次触发、新设备首次登录必须校验（`[已实施]`）。
- **要求补齐**（`[待实施]`，按优先级）：
  1. AI 对话/生成端点限流（防 token 额度盗刷）——护栏已有请求上限，补 IP/用户维度限流；
  2. 密码相关写操作（改密/重置）限流；
  3. 公开读取接口（联盟前台/公开资源）防爬限流。
- **文档口径修正**：`系统功能清单.md` 原称「接口限流」为平台级能力，实际仅覆盖上述端点；本文档为准——未挂限流器的接口**不视为已限流**。

## 6. 上传与文件安全

| 项 | 要求 | 状态 |
|----|------|------|
| 类型校验 | 扩展名白名单 + **magic bytes 嗅探**（防止改扩展名绕过） | `[待实施]`（现状仅白名单） |
| 大小 | 单文件 ≤ 10MB（请求体上限需计入 multipart 开销，实际限 `10MB + 头部`） | `[已实施]` |
| 存储 | 存 `data/uploads/{tenantID}/`，目录禁止执行权限；下载走 `Content-Disposition: attachment` 或内容安全响应头 | `[已实施]` |
| 访问控制 | 签名 URL 或登录态混合鉴权（`OptionalJWT`），跨租户 403 | `[已实施]` |
| 压缩炸弹 | zip/归档解包前校验展开体积与文件数上限 | `[待实施]` |

## 7. 可观测性

- **现状**：`/health`、`/health/ready`（DB+Redis）、`/metrics`（Prometheus：请求量/耗时/5xx + DB 连接池）、操作日志异步化审计。
- **要求补齐**（`[待实施]`）：慢查询日志、5xx/限流告警阈值、AI 调用失败告警；审计日志含操作人/租户/IP/目标资源，支持按租户检索。

## 8. 敏感信息脱敏与日志

- 身份证号、手机号等 PII 展示脱敏（`[已实施]` 部分）；日志禁止打印密码、api_key、token、身份证明文。
- 第三方 AI 上游错误 message 透传时，须过滤 `sk-` 等密钥前缀与可能回显的敏感片段（`[待实施]`，见 ai-development.md）。
