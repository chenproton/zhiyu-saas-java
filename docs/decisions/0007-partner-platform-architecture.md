# 0007: 企业平台（Partner）架构——企业全局实体 + 专家账号直绑

- 状态：已接受
- 日期：2026-08-14
- 取代：无

## 背景

联盟模块最初把「企业」当作学校租户内的联盟台账数据（alliance_enterprises 存于学校 tenant 域）。企业端独立门户（partner 平台）上线时出现两种建模路线：企业继续按学校域台账、学校与企业各自维护一套企业档案（影子数据）；或企业提升为全局独立实体、学校通过关联引用同一企业。

## 决策

1. 企业 = 全局独立实体：企业档案全局唯一（迁移 142 改造），学校通过 alliance_enterprise_links 建立「合作/关注」等关联引用，而非各校自建企业副本。
2. 专家数据存企业侧：联盟专家档案与企业绑定，学校侧按授权（alliance_resource_grants，146）读取。
3. 企业账号直绑取代影子账号：企业专家登录账号直接 user_id 绑定专家档案（142 加 user_id），废弃「共建导师影子账号」体系（154 删除关联表、155 清理遗留数据）。
4. 企业端资源共建：企业侧编辑的岗位/场景以来源标记（145 source_type=enterprise）归属企业，由学校端审核发布。

## 备选方案

1. 企业继续做学校域台账，partner 独立建企业库：两套企业数据双写，同一企业多校各自维护，档案互相矛盾且需同步机制。否决。
2. 影子账号保留（企业专家无真实登录账号，由平台生成占位账号）：账号无法自助登录/改密，安全与体验双差。否决（154/155 已删除该体系）。

## 后果

### 正面
- 企业档案单一事实源，多校共享同一企业画像与品牌数据。
- 专家有真实账号，支持自助登录、改密、参与企业侧共建。

### 负面 / 代价
- 全局企业实体引入跨租户读路径（学校读企业全局数据），需依赖授权表 + 公开字段（is_public）双重把关，越权面靠 handler 校验。
- 迁移 142/146/154/155 属破坏性改造（TRUNCATE 联盟数据、删表），历史环境升级需按发布说明执行。
